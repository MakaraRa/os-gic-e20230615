## Task 1 — File Creator and Reader

### File Creator
The library version uses standard C library functions to create and write a file. The system-call version uses `open()`, `write()`, and `close()` directly.

Both versions created the same file content.

### File Reader
The library version uses `fopen()`, `fgets()`, and `fclose()`. The system-call version uses `open()`, `read()`, and `close()`.

Both versions displayed the same file content.

### Questions

1. The `read()` system call returns the number of bytes successfully read. It returns 0 when the end of the file is reached and -1 when an error occurs. Unlike `fgets()`, it does not automatically stop at a newline or add a null terminator.

2. A loop is needed because one `read()` call may not read the entire file. The program continues reading until it reaches the end of the file or an error occurs.

## Task 2 — Directory Listing

The library version uses `printf()` to display directory entries. The system-call version uses `write()` to display the output and `snprintf()` to format each filename and file size.

### Questions

1. `readdir()` returns a pointer to a `struct dirent` representing the next directory entry. Its `d_name` member contains the entry name.

2. `stat()` provides file information such as size, file type, permissions, owner, group, inode number, and timestamps.

3. `write()` sends bytes to a file descriptor. It does not format numbers or strings, so `snprintf()` is used to convert the filename and size into formatted text first.

## Task 3 — System Call Tracing

The `strace` utility was used to observe the system calls made by the library and system-call versions.

Trace files and summaries are stored in `task3_strace/`.

### Questions

1. The total system-call counts are recorded in `strace_summary_lib.txt` and `strace_summary_sys.txt`. The library version may make additional calls for runtime and library operations. Compare the totals in these files.

2. The full traces show additional calls such as memory-management or file-information calls when present. Calls such as `brk()` and `mmap()` are commonly used for memory allocation, while `fstat()` retrieves file metadata. These calls support library and runtime operations.

3. The actual `write()` calls made by the library version can be seen in `strace_lib_task1.txt`. Standard I/O may buffer output, so a library output operation does not necessarily correspond to one immediate system call.

4. A library function provides a convenient user-space interface and may internally use one or more system calls. A system call directly requests a service from the operating-system kernel.

## Task 4 — The /proc Filesystem

System information, process information, and kernel module information are recorded in the `evidence/` directory.

### Questions

1. `/proc` is a virtual filesystem. It is not a normal filesystem storing files permanently on disk. Its entries provide information generated by the Linux kernel about processes and system resources.

2. A monolithic kernel provides many operating-system services inside kernel space. A microkernel keeps a smaller core in kernel space and moves more services into user space. Linux uses a monolithic kernel design, with support for loadable kernel modules.

3. The memory map shows regions such as executable code, heap, stack, and shared libraries. These regions represent different parts of a process's virtual address space.

4. The output of `uname -a` includes the operating-system name, hostname, kernel release, kernel version/build information, machine architecture, and other system details.

5. `/proc` demonstrates that the kernel manages and provides information about processes and hardware resources. User-space programs can request this information through the virtual filesystem rather than directly controlling hardware.
